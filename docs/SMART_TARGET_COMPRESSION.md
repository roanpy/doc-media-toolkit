# 智能目标容量压缩规格

状态：Grill 已完成；PPTX、附带媒体及 DOCX/PDF/XLSX 图片压缩后端已进入正式主线
适用仓库/分发：`doc-media-toolkit`（导入包：`pptx_tools`；CLI 兼容名：`pptx-tools`）
目标分支：`main`

当前实现检查点：正式主线的 PPTX/附带媒体已具备关系图扫描、显示面积/复用权重、联合
预算、双尺度质量门禁、最多两轮容量纠偏、一轮质量回补、计划签名去重、进度单调、安全/
强制独立输出、Windows GPU 探测与 CPU 回退和共用队列。DOCX、PDF、XLSX 图片压缩后端
已通过同一 `compact_input_path` 入口接入正式 GUI/CLI，并继续各自执行格式安全合同。

## 1. 目标

本项目不是专业视频或图片压缩软件。智能压缩是 Doc Media Toolkit 的附加能力，产品
定位是文档处理与媒体管理工具箱；视频和图片算法主要服务文档容量优化。独立媒体
只作为同一压缩队列的附带输入，可通过拖放或“添加文件”进入；不新开页面、窗口、
独立用户接口或另一套设置，目标容量、预设、质量阈值和 GPU 策略与文档共用。不得
因此改变产品名称、首页主叙事或把工程演变成通用媒体编辑器。

在质量底线优先的前提下，让 PPTX、独立图片以及 DOCX/DOCM、
PDF、XLSX/XLSM 尽可能接近用户为**每个文件**指定的目标容量。算法必须根据
媒体的实际显示面积、内容类型、复用次数和质量评估分配容量，不能把“极致压缩”
实现成统一降分辨率或统一降低码率。

完成范围还包括通用设置、批处理、报告、自动质量纠偏、测试、实验构建、用户文档、技术
文档和架构说明。格式后端须各自通过结构、布局和运行时门禁；门禁失败时拒绝发布输出。

## 2. 不可破坏的安全约束

- 源文件不被覆盖；安全版与用户另行确认的强制版必须是不同输出文件。
- 目标容量安全模式中，质量底线参与规划和审计；SSIM 未达用户阈值时保留当前压缩
  候选，标记 `below_threshold` 并报告原因和差值，避免为了追求质量而把整份文档恢复
  成原始大文件。强制模式触及绝对红线仍恢复原素材；普通安全模式的结构/解码/元数据
  审计失败也恢复原素材。
- 强制模式也有绝对质量红线；仍无法达到目标时报告“不可能”，不得继续无脑降质。
- 安全版超过目标时，UI 可显示“尝试强制版”，但不得自动运行。点击后先展示预计可
  压缩空间、涉及素材和绝对质量红线，并经二次确认后生成独立强制版；安全版始终
  保留。预检已证明强制版不可能达标时不显示执行按钮，只说明原因。
- 不允许自动删除或静音音轨，可以降低音频码率。
- 不允许自动扁平化、删除或改写嵌入的 Excel、Word、PDF、字体、OLE 等对象。
- 所有自动判断必须在本地完成，不使用网络或 AI 分类。
- 任何不确定的引用、共享关系或格式能力都按“保留原样”处理。
- 不自动下载或访问外部链接图片、视频和云端资源，不修改外部 URL、关系或缓存。
  可验证的包内本地缓存只作为独立内嵌资源处理；缺失引用、断链和循环关系保持原样
  并报告，不阻止其他结构正常的内嵌素材。任何网络访问不属于压缩功能。
- 某个媒体因损坏、解码器限制或评分工具异常而无法完成质量审计时，恢复该素材的
  原始版本；其他可验证素材继续处理。目标模式只对“已完成评分但低于 SSIM 阈值”的
  候选保留压缩结果，不得把无法验证当成通过。不得用体积变化代替质量证据，强制模式
  也不能绕过无法验证的素材。最终文件因此超过目标时，报告必须说明恢复原因和容量差值。

## 3. 容量语义与批处理

- UI 中 `1 MB = 1,000,000 bytes`，不是 MiB。
- 批处理时，目标容量独立应用于每个选中文件，不是整批共享总容量。
- 目标模式必须按最终输出文件实测大小闭环，不能只相信编码器估算值。
- 目标不是要求最终字节数与目标严格相等，而是在质量底线内尽量接近。正常达标文件
  不超过目标；如果继续压缩会造成明显质量损失，则允许安全版高于目标并明确报告。
- 低于目标时不通过填充无用数据凑容量；只有存在真实质量收益且仍不超过目标时才
  回补质量。
- 默认把目标的 `95%–100%` 视为足够接近。低于 95% 且存在能提高真实画质、同时仍
  不超过目标的候选时，执行已约定的最多一轮质量回补；没有更高质量候选或素材已是
  最高质量时，允许低于 95% 并在报告中说明。
- 源文件已经小于或等于目标时完全跳过，不重新编码或生成重复副本；如仍需减小体积，
  用户应清空目标并显式选择普通压缩预设。
- 首次输出明显小于目标时，最多自动执行一轮质量回补，利用剩余容量提高质量。
- 首次编码和打包后最多执行两轮容量/质量纠偏，再加最多一轮质量回补。三轮后仍未
  收敛时停止，保留最后一个通过质量和结构验证的安全版本。
- 不设置固定的整文件分钟数上限；每个编码进程采用与素材时长相关的超时保护。用户
  可随时取消，取消后不得发布半成品。
- 目标模式的报告必须包含：目标字节数、实际字节数、差值、是否达标、质量底线、
  命中底线的素材、每轮调整原因和最终采用的编码路径。
- 固定 `4 MB` 预留将改为根据不可压缩内容和实际 ZIP 重打包偏差计算的动态预留。

## 4. 质量与容量联合分配

优化目标是在最终容量约束下最大化加权感知质量，而不是先把视频吃完预算、再把
剩余容量交给图片。

同一套智能规则引擎用于普通高质量/均衡/极致预设和目标容量模式。普通预设也使用
面积、内容类型、复用次数和质量底线，但不为容量反复编码；目标容量模式在同一规则
上增加预算、两遍编码、有限纠偏和质量回补，不维护第二套独立算法。

### 4.1 通用流程

1. 预检容器、关系图、媒体、不可压缩内容和目标是否理论可达。
2. 为每个素材建立从高质量到质量底线的离散候选阶梯。
3. 根据显示面积、内容类型、复用次数、时长和节省字节计算降档代价。
4. 每次选择“单位节省字节的加权质量损失最低”的候选，直到进入目标预算或触底。
5. 编码并重新打包，读取真实最终容量。
6. 做素材质量审计和容器结构验证；目标安全模式对已评分但低于用户阈值的素材保留候选
   并标记，强制绝对红线或解码/结构/元数据失败则选择性恢复原件。
7. 需要时执行有限纠偏；明显低于目标时最多执行一轮质量回补。
8. 输出安全版及完整报告。强制版只有在用户明确确认后才另行生成。

预检发现目标小于“不可压缩内容 + 容器最低开销”时，该文件直接标记“目标不可能”，
不启动编码；批处理继续处理其他文件，结束后统一展示最低理论容量和主要占用项。强制
模式也不能突破不可压缩内容，不提供无效入口。

质量判定采用多项门槛全部通过，不以加权平均掩盖单项缺陷。图片校验源尺寸与显示
尺寸 SSIM、文字/线条边缘、分辨率、比例、Alpha、ICC、方向、DPI、动画/多页结构；
视频校验双尺度抽帧 SSIM、分辨率、比例、时长、帧数、帧率和音轨结构；文档容器
校验关系、内容类型、非媒体部件、对象锚点和格式专用不变量。SSIM 低于阈值与无法
解码/结构失败分开处理：前者在目标模式保留候选并报告，后者恢复原素材。首版不强制
增加 VMAF 等额外运行库。

### 4.2 视频

- 视频基础 SSIM 阈值按预设默认为高 `0.95`、均衡 `0.93`、低体积 `0.90`，用户手动
  设置后跨档位和会话保留；强制模式绝对红线为 `0.90`。
- 复用现有按幻灯片显示面积计算的分辨率、帧率、视频码率和音频码率规则。
- 目标容量模式默认使用 CPU `libx264` 两遍编码以提高容量准确性。
- Windows GPU 路径支持 NVENC、QSV、AMF；普通预设可默认使用 GPU。
- “GPU 加速目标容量”位于通用设置，默认关闭并记忆上次选择。
- GPU 目标模式按编码器分别做闭环；单个素材失败时回退 CPU，不拖垮整份文件。
- 不采用会显著降低 PowerPoint 通用兼容性的 H.265/AV1 作为默认输出。

### 4.3 图片

- 安全模式图片基础 SSIM 阈值默认 `0.99`。
- 强制模式绝对红线：照片类图片 `0.96`；截图、文字、表格、线稿和 Logo `0.98`。
- 透明图除 SSIM 外还必须校验 Alpha 通道，不允许透明边缘出现明显破坏。
- 小面积素材可由算法降低实际阈值，但不得低于对应绝对红线；大面积、全屏和多次
  复用素材提高实际阈值。通用设置只开放视频与图片基础阈值，报告显示实际采用值。
- 独立图片首版支持静态 JPEG、PNG、WebP、TIFF、BMP。
- 独立图片默认保持原格式和扩展名，不自动转换。以后可增加默认关闭的显式格式转换
  选项；开启后也必须输出新扩展名、不覆盖原文件并完整保留可承载元数据。
- 动画 GIF、动画 WebP 只有在完整保留全部帧、帧时序、循环次数和透明度时才允许
  压缩；否则安全模式跳过。
- 多页 TIFF 必须完整保留全部页面，否则安全模式跳过。
- HEIC、AVIF 首版不支持；只有解码器能够稳定随安装包交付并通过兼容性测试后才加入。
- 图片按显示尺寸评估，不只按源像素和压缩包内字节数。
- 显示面积、多个引用中的最大显示尺寸和复用次数共同决定质量权重。
- 本地确定性分类区分照片、截图/文字、线稿/Logo、透明图和近似纯色图。
- 用户只配置视频与图片的基础质量阈值；全屏、半屏、小图等内部阈值由算法调整，
  不暴露成一排高级参数。报告记录实际应用阈值。
- 无透明度且确定为照片、没有文字或线稿风险的 PNG，只有在显示尺度质量审计通过时
  才可转为 JPEG，并同步校验关系和内容类型。
- 精确 SHA-256 重复媒体只有在完整关系图、内容类型和包结构验证通过后才可合并。
- 完整关系图确认无引用的孤立媒体可从输出副本删除；有歧义即保留。
- 裁剪区像素物理删除只允许在强制模式、图片仅被引用一次、裁剪关系明确且保留边缘
  安全区时执行；共享图片不处理。

## 5. PPTX 音频与不可压缩内容

- 独立嵌入的旁白、背景音乐、WAV、MP3 等音频纳入预算。
- 必须保持时长、播放关系、声道语义和是否存在音轨；只允许降低码率，不允许删除。
- 若 FFprobe 明确报告音频时长为零且最多只有一帧，视为源文件的异常空音轨：不尝试
  重编码，不静音或删除该流，直接保留原媒体字节和关系，并在报告中写入
  `unusable_audio_stream_preserved`；该媒体按原大小计入目标预算。
- 未主动降帧的 VFR 视频必须保留源时间戳；仅在档位明确要求降帧时才重采样到目标
  帧率，并对输出帧数做目标校验。
- 嵌入的 Office/PDF/OLE、字体及其他不安全对象作为不可压缩字节计入预检和报告。

## 6. 文档格式的布局合同

DOCX/DOCM、PDF、XLSX/XLSM 走独立分支。任何分支只有在格式专用结构测试和视觉
验证稳定后才能合入主线。

### 6.1 Word

- 支持 `.docx`、`.docm`；不支持旧二进制 `.doc`，也不自动转换。
- 首版不支持 `.dotx`、`.dotm`；普通文档分支稳定后再单独增加模板行为测试。
- 只原位替换经关系图确认的图片资源，覆盖正文、页眉页脚、脚注尾注、批注和文本框
  等引用位置。
- 不改变分页、页面尺寸、段落与对象布局、样式、批注、修订、字段、链接和内容控件。
- `.docm` 的 VBA 内容保持原字节不变。
- 源文件和输出文件必须逐页渲染并检查；结构检查不能替代视觉检查。

### 6.2 Excel

- 支持 `.xlsx`、`.xlsm`；不支持旧二进制 `.xls`，也不自动转换。
- 首版不支持 `.xltx`、`.xltm`；普通工作簿分支稳定后再单独增加模板行为测试。
- 只原位替换关系图确认的图片资源。
- 不改变公式、缓存值、图表、批注、对象锚点、宏、工作表结构、打印区域、页面设置
  和分页。
- `.xlsm` 的 VBA 内容保持原字节不变。
- 结构验证覆盖公式/图表/关系/宏哈希，视觉验证覆盖定义打印区域和可渲染工作表。

### 6.3 PDF（含扫描件）

- 按页识别数字页、扫描页和混合页，不把整份文件粗暴归为一种类型。
- 数字 PDF 只替换图片 XObject，保留矢量、文字、字体、链接、批注、书签、附件、
  表单和页面尺寸；普通数字 PDF 不整页栅格化。
- 扫描页压缩页面图像但保留页面几何；已有 OCR/可搜索文字层原样保留。
- 没有 OCR 的扫描件不自动 OCR。
- 禁用可能发生字符替换错误的有损 JBIG2；黑白扫描优先使用 CCITT Group 4 或无损
  编码，照片/彩色扫描根据质量门槛选择 JPEG 或无损编码。
- 无法安全原位替换的内联图片保持原样并在报告中说明。

### 6.4 图片元数据

- 安全模式保留全部可识别元数据，包括 ICC、EXIF 方向、DPI、动画信息、版权、GPS、
  拍摄设备、日期和内嵌缩略图。
- 元数据占用导致无法达到目标时，按不可压缩内容报告，不静默删除。
- 隐私清理是以后独立、显式的功能，不与容量压缩绑定。
- 格式转换无法承载原元数据时，安全模式放弃该次转换并保留原资源。

## 7. 签名、加密与凭据

- 带数字签名的 PDF、Word、Excel 在安全模式下拒绝压缩并明确提示。
- 只有用户显式选择“生成未签名副本”才允许处理，且输出文件名必须清晰区分。
- 加密文件按文件临时询问密码；密码只在本次任务内存中使用，不写配置、报告或日志。
- 未提供密码或密码错误时跳过该文件。
- 压缩后的文件继续加密并沿用同一密码，不得意外解除保护。

## 8. 通用设置

以下项目放在通用设置中，并持久化：

- 视频基础质量阈值。
- 图片基础质量阈值。
- GPU 加速目标容量开关（默认关闭，记忆上次选择）。
- 普通压缩预设的硬件加速策略。
- 目标模式的进度显示遵循全局单调递增规则；容量重试使用编码计划签名，计划不变时
  不重复编码。

算法内部的面积分级、语义分类参数和每种编码器校正参数不直接暴露给用户；实际应用
结果写入报告。

压缩设置只保留与多个文档格式共同相关的少量选项；格式专用细节留在压缩任务内部，
不得把通用设置扩张成视频/图片专业编码面板。编码器和格式专用依赖按任务需要加载，
不拖慢水印、素材库和其他核心功能启动。

压缩保留为工具箱中的二级工具或现有压缩页，不占据首页核心位置；首页不宣传专业
视频编码或图片编辑能力。GPU、编码器等细节默认折叠。独立视频/图片与文档共用拖入、
添加、任务队列和设置，不单设接口，也不扩展剪辑、滤镜或专业转码矩阵。

### 8.1 报告

- 每个输出同时生成机器可读 `.report.json` 和人可读 `.report.md`。
- GUI 完成页只展示核心摘要和异常，并可打开 Markdown 详情；日志不重复完整报告。
- 批处理额外生成汇总 Markdown，各单文件报告仍独立保留。
- 报告不得包含密码、临时路径或其他敏感信息。

## 9. 发布与变更门槛

### 9.1 当前发布策略

- DOCX、PDF、XLSX 格式后端已合并 `main`（8d13d72，经用户明确批准）并随包分发；
  正式 GUI 压缩页与 CLI 已接入（`compact_input_path` 按后缀路由），与
  PPTX/附带媒体核心同队列对用户可见。
- 队列包含这三类格式时，GUI/CLI 要求显式目标容量（MB）且图片预设不能为
  "不压缩"；PDF 压缩后的自动画质评估不适用（非 ZIP 结构），GUI 跳过并记录日志。
- 实验应用名与可执行文件名带 `Experimental`，使用独立应用标识、`QSettings`、缓存、
  日志和临时目录；不得自动读取或修改正式版素材库及最近任务记录。
- 实验产物放在 `dist/experimental/<branch>/<commit>/`，输出文件名带
  `_experimental`，UI 持续显示实验版标识。
- 每次实验构建附提交 SHA、测试结果和人工验收清单，不覆盖、升级或卸载正式版。
- 格式分支的合并门槛：测试全过并经用户明确批准（已于 8d13d72 满足）；后续格式
  变更走正常 `main` 流程。

### 9.2 已完成的开发顺序

历史开发顺序：

1. `agent/smart-target-compression-core`：PPTX、独立图片、通用设置和联合容量闭环。
2. `agent/smart-target-compression-docx`：DOCX/DOCM。
3. `agent/smart-target-compression-pdf`：数字、扫描及混合 PDF。

每个分支必须独立通过：

- 单元测试与真实容器端到端测试。

- 原始/输出结构不变量检查。
- 与格式相匹配的逐页或逐素材视觉质量检查。
- 目标容量可达、质量触底不可达、编码偏差纠正和质量回补场景。
- Ruff、完整测试集、构建和安装包冒烟测试。
