# XLSX/XLSM 智能压缩后端

状态：已随统一格式包合并 `main`（8d13d72），随包分发；正式 GUI 压缩页与 CLI 已接入（`compact_input_path` 按后缀路由），需显式目标容量且图片预设不能为"不压缩"。

## 范围与策略

- 支持 `.xlsx`、`.xlsm`；旧二进制 `.xls` 和模板格式不自动转换或处理。
- 只替换由 OOXML 内部关系明确引用的 `xl/media/` 图片；外部链接、未知关系和未确认
  的对象保持原样。
- 解析工作表到 Drawing、Drawing 到图片的关系，并读取 one/two-cell anchor 或图片变换
  尺寸，以工作表打印页为参照估算显示面积。无法确定锚点的图片按全尺寸保守处理。
- 图片复用次数、最大显示面积和内容类型进入核心目标容量与质量规则；最多两轮容量
  纠偏和一轮质量回补。计划未变化时停止，避免重复重写工作簿。

## 结构合同

- 除已验证图片流外，ZIP 成员集合及每个成员的解压字节必须完全一致。因此公式与缓存
  值、样式、共享字符串、表格、图表、透视表、切片器、批注、Drawing、对象锚点、
  工作表、打印区域、页面设置、外部链接和自定义 XML 均不改写。
- `.xlsm` 的 `vbaProject.bin` 及全部非图片宏部件保持原字节。
- 数字签名工作簿拒绝处理；无安全解密和重加密运行时时，加密或无效包失败关闭。
- 源文件、已有输出和正式软件配置均不覆盖。目标已满足时只写跳过报告，不产生副本。

## 布局与 PDF 导出门禁

- XLSX/XLSM 可以导出 PDF，当前只作为压缩后的布局验收能力，不自动加入正式
  UI。Windows 优先 Microsoft Excel COM，兼容 WPS Spreadsheets COM，并以
  LibreOffice Calc 作为跨平台回退；macOS/Linux 使用 LibreOffice Calc。
- 输入输出分别导出 PDF，页数、MediaBox、旋转和逐页可提取文字必须一致。
- PDFium 以相同分辨率逐页渲染；逐页 SSIM 不低于 `0.985`，边缘相似度不低于
  `0.98`。导出引擎缺失或验证失败时拒绝发布输出。

## 产品边界

该后端已并入 `main`、随 Python 包分发并接入正式 GUI/CLI。它不重算或改写工作簿，不处理旧 `.xls`，不扁平化工作表，也不把
Excel/PDF 导出包装成独立产品能力。
