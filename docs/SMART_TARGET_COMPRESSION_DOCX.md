# DOCX/DOCM 智能压缩后端

状态：已随统一格式包合并 `main`（8d13d72），随包分发；正式 GUI 压缩页与 CLI 已接入（`compact_input_path` 按后缀路由），需显式目标容量且图片预设不能为"不压缩"。

## 范围

- 仅处理 `.docx`、`.docm` 中由 OOXML relationship 明确引用的 `word/media/*` 图片。
- 正文、页眉页脚、脚注尾注、批注、文本框等只要使用标准图片 relationship，均由
  全包关系图覆盖；不按文件名猜测引用。
- 图片保持原部件路径、扩展名和容器格式；非媒体 ZIP 部件逐字节保持。
- `.docm` 的 `vbaProject.bin`、`vbaData.xml` 逐字节校验。
- 安全/强制阈值、最多两轮容量纠偏和一轮质量回补复用核心规则；新图片计划未变化时
  直接停止，避免重复重写 Word 文档。
- 强制后端必须同时收到“安全输出存在且仍超目标”和显式二次确认，且始终另存；
  已存在的输出拒绝覆盖，任一步失败删除本轮半成品。
- 后端默认启用 `validate_render=True`：Windows 依次调用本机 Microsoft Word COM、
  WPS Writer COM、LibreOffice；macOS 依次使用 LibreOffice、Pages。输入输出导出为
  PDF 后校验页数、页面尺寸、旋转、逐页文字、SSIM 与边缘相似度；缺少可用引擎时
  失败关闭。单元测试可显式关闭该门禁以只验证包结构。
- 源文件已满足目标时只生成报告并返回源路径，不创建重复文档。

## 失败关闭

- 数字签名文档拒绝处理；本分支不提供“生成未签名副本”。
- 加密或非 ZIP Word 文件在没有可靠解密并重新加密运行时的情况下拒绝处理；不会
  意外输出未加密副本。
- 不支持 `.doc`、`.dotx`、`.dotm`，也不自动转换。
- 无法解码、无法完整保留元数据、动画或多页结构的图片恢复原件。

## 验收门槛

- 输入输出成员集合一致；除已替换图片外所有部件逐字节一致。
- 宏部件逐字节一致，关系和内容类型不改写。
- 使用本机 Office/WPS/LibreOffice/Pages 做输入输出逐页渲染，页数、页面尺寸、页面
  几何和文字一致，逐页 SSIM 不低于 `0.985`、边缘相似度不低于 `0.98`；该视觉验证
  已经实测渲染通过（逐页 SSIM 约 0.9998），并经用户明确批准后接入正式 UI。
