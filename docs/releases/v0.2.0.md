# Doc Media Toolkit 0.2.0

> [!IMPORTANT]
> This release is a draft. The source tag may be reviewed, but prebuilt binaries
> must remain private release candidates until the public-binary gate passes.

## What this release solves

Doc Media Toolkit reduces oversized PPTX files by allocating a practical media
budget, compressing embedded video and images, auditing the result, and raising
quality when the first result is unnecessarily aggressive. It also turns document
media into reviewable, reusable assets instead of leaving copies scattered across
presentations.

## Before installing

| Platform | Requirement | Package status |
| --- | --- | --- |
| macOS Apple Silicon | macOS 13 or later | Native candidate verified; Developer ID signing and notarization still required |
| macOS Intel | macOS 13 or later | Native candidate verified; Developer ID signing and notarization still required |
| Windows x64 | Formal Windows client baseline is still being validated | Portable onedir candidate and Authenticode signing still required |

See the [installation and platform guide](https://github.com/roanpy/doc-media-toolkit/blob/main/docs/INSTALL.md)
before choosing a package. Do not disable Gatekeeper or SmartScreen to run an
unknown or mismatched publisher.

## Highlights

- Smart target-size compression for PPTX embedded media with quality thresholds,
  safe retries, post-compression auditing, and quality promotion.
- Image-based PPTX/PDF watermark export, including embedded-video watermark
  processing and reinsertion where supported.
- PPTX video asset library with SHA-256 deduplication, conservative media identity,
  deck associations, reviewed restoration, recoverable cleanup, and health checks.
- Supporting embedded-image compression for DOCX/DOCM, PDF, and XLSX/XLSM while
  preserving document layout and text structure.
- Optional AI-assisted naming, classification, and grouping suggestions with
  explicit review before any library change.
- English-first application shell, compression, watermark, help, documentation,
  and anonymous screenshots, plus Simplified Chinese support. Video and image
  library operations remain Chinese-first.

## Upgrade and data safety

- Finish active jobs before upgrading.
- Back up each complete video or image library directory, including managed media,
  manifests, `.bak` files, quarantine, and reports.
- Compression and watermark workflows save a new output by default.
- Version 0.2.0 keeps both library schemas at version 1; no library migration is
  expected within this release.

## Known limitations

- The image library is ancillary and has a smaller real-world validation surface
  than PPTX compression, watermarking, and the video library.
- Video and image library operations are not yet fully translated into English.
- Office-format export may require Microsoft Office, WPS, LibreOffice, Keynote, or
  Pages depending on the platform and input format.
- Windows client support must be confirmed on physical Windows 10/11 systems before
  a public Windows package is declared supported.
- Public binaries remain blocked until signature, notarization where applicable,
  malware scan, SBOM, native inventory, Qt redistribution, and FFmpeg corresponding
  source evidence all pass.

## Verification and supply chain

Every future public package must include or link to:

- SHA-256 checksums;
- a CycloneDX SBOM and native-file inventory for that exact artifact;
- valid platform signing and, on macOS, notarization evidence;
- a clean malware-scan report;
- the exact FFmpeg version and build configuration; and
- corresponding source delivery for a bundled GPL FFmpeg build.

The replacement build path pins FFmpeg 8.1.2 and x264 source by SHA-256 and emits
the matching platform source archive automatically. The withdrawn Homebrew/Gyan
binaries are not reused.
