# PDF 智能压缩后端

状态：已随统一格式包合并 `main`（8d13d72），随包分发；正式 GUI 压缩页与 CLI 已接入（`compact_input_path` 按后缀路由），需显式目标容量且图片预设不能为"不压缩"。PDF 非 ZIP 结构，压缩后的自动画质评估不适用，GUI 会跳过并在日志说明。

## 范围与策略

- 按页识别 `digital`、`scanned`、`mixed`，依据 Poppler 给出的图片实际显示面积和
  可提取文字层判断，不以整份文件粗略归类。
- 只原位替换可安全解码的间接 Image XObject；内容流、矢量、文字、字体、页面框、
  旋转、链接、批注、书签、附件、表单、页面标签、文档元数据和目录设置保持。
- 扫描页已有 OCR/可搜索文字层原样保留；没有文字层时不自动 OCR。
- 1-bit 扫描图使用无损 CCITT Group 4。照片可使用 JPEG，但必须通过素材双尺度
  SSIM、边缘、alpha 和最终逐页渲染门禁。
- 图片按实际页面占比和复用次数参与目标预算；最多两轮容量纠偏和一轮质量回补。新
  计划未变化时保留当前安全输出，不重复生成 PDF。

## 失败关闭

- 不生成有损 JBIG2。源文件中的 JBIG2 保持原样，不解码后重复有损压缩。
- 内联图片、软蒙版/显式蒙版、ImageMask、ICCBased/Indexed/Separation 色彩空间、
  可选内容和附带图片元数据的复杂 XObject 保持原样并写入报告。
- 数字签名和加密 PDF 拒绝处理；当前没有足以保持原签名/所有者密码/权限和算法的
  安全重签名或重加密运行时。
- 强制模式必须同时收到仍超目标的安全输出与显式二次确认，且另存；既有输出不覆盖，
  失败删除本轮半成品。

## 结构与视觉门禁

- 输入输出逐页内容流解码哈希相同，证明绘制指令和布局矩阵未改写。
- 页数、Media/Crop/Bleed/Trim/ArtBox、旋转、逐页文字、注释、表单值、附件哈希、
  书签、页面标签、Info/XMP 和关键 Catalog 设置一致。
- 最终输入输出分别由 Poppler-Cairo 和已内置的 `pypdfium2` 以 144 DPI 渲染为 PNG，
  两套结果都必须通过。页数和像素尺寸必须相同，逐页 SSIM 不低于 `0.985`、边缘
  相似度不低于 `0.98`。不使用 Poppler Splash（`pdftoppm`）作为质量裁决器，因为它
  对重编码共享图像 XObject 的样本存在局部内容漏绘，而 Cairo 与 PDFium 结果一致。
- 页面图片面积分类依赖 Poppler `pdfimages`；正式运行须在各平台内置或
  提供已验证的 `pdfimages` 与 `pdftocairo` 运行时，缺失时拒绝压缩而不是降级为
  不可靠猜测。
- `pypdf` 只读提取和比较结构指纹；`pikepdf` 原位替换通过安全检查的图片流，避免
  通用 PDF 重写器破坏复杂对象引用。

## 产品边界

该后端已并入 `main`、随 Python 包分发并接入正式 GUI/CLI。它不是通用 PDF
重写器，不提供 OCR、扁平化、隐私清理、签名移除或密码破解。
