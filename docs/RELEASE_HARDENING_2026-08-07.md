## 3. 根因与修复

固定的 1180 px 窗口断点无法表达右侧内容区的真实宽度，也没有随“尝试强制版”按钮
显示状态变化。结果是在临界尺寸把控件塞进不足的一行，由 Qt 静默压缩按钮或文案。

修复位于 `src/pptx_video_compactor_gui.py`：

1. 从根布局边距、左栏宽度、栏间距和设置卡片边距计算评估行真实可用宽度；
2. 用现有控件的最小宽度与 `sizeHint` 计算合并所需宽度；
3. 常驻的“画质评估/提档优化”始终计入，强制版按钮仅在显示时计入；
4. 空间足够时按钮在阈值行靠右，不足时移回标题行；
5. 强制版按钮显示状态改变后立即重算布局。

没有新增布局框架、依赖、滚动区或固定机型阈值。

## 4. 1100 px 决策数据

默认操作需要 828 px；强制版按钮可见时需要 922 px。实测如下：

| 窗口宽度 | 评估行可用宽度 | 默认布局 | 强制按钮可见 |
| ---: | ---: | --- | --- |
| 880 | 560 | 分行 | 分行 |
| 1000 | 680 | 分行 | 分行 |
| 1100 | 780 | 分行 | 分行 |
| 1180 | 800 | 分行 | 分行 |
| 1280 | 900 | 同行 | 分行 |
| 1440 | 1060 | 同行 | 同行 |

因此 1100 px 强行同行会少 48 px，并导致完整文案或按钮被压缩；当前分行是满足文字
完整、无重叠和不改变业务控件的最小安全方案。18 组压缩页尺寸中控件中心偏差最大
0.5 px。

### 7.1 2026-08-08 缩放后控件高度补充修复

- 压缩页与水印页原先对下拉框、数值框和操作按钮使用固定 30/32 px 高度；统一壳
  重新套用页面样式后，Qt 的实际 `sizeHint` 可能变大，导致控件底部被压缩或与
  相邻表头贴合。

  行的间距统一为 8 px。没有改变业务处理、输出路径或数据协议。
- 离屏回归矩阵新增“控件高度不得小于 `minimumSizeHint`”断言；水印、压缩、视频库
  和图片库四个工作区均纳入检查。
- `b1b62c4` 的本地 macOS arm64 DMG 已完成 `hdiutil verify`、只读挂载、深度签名
  校验、内置 FFmpeg/FFprobe 检查和 8 秒离屏启动冒烟；SHA-256 为
  `4b00c508a6d3fe06fdc8eca5559fa08d6642abcd092def707b520c8c2202296b`。
