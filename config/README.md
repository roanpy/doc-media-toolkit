# 配置说明

[English guide](README.en.md)

这个目录放的是压缩策略配置。现在的默认思路是：

- 视频在页面里占比越大，默认分辨率越高
- 全屏或接近全屏的视频优先保更多清晰度和更高音频码率
- 小视频优先让位给总体体积目标

项目声明：基于 GPT-5.5 辅助工程流程打造。

## 预设文件

- `default.json`
  历史兼容文件，当前与 `balanced.json` 相同。
- `balanced.json`
  默认推荐。平衡画质和体积。
- `high.json`
  更偏保真。
- `aggressive.json`
  更偏极限压缩。

默认运行结束后，工具会清理过程产物，只保留：

- 原始 `pptx`
- 转换后的 `pptx`

如果你要保留 `.report.json` 和压缩后视频目录，运行时加 `--keep-artifacts`。发生普通处理错误时，工具也会把可用的诊断报告/过程视频复制到源文件旁边，便于排查；手动停止和成功完成都会清理临时目录。

## `default.json` / `balanced.json`

### `render_limits`

- `max_output_height`
  输出视频的最大高度上限。默认 `1080`。
- `max_long_edge`
  输出视频最长边上限。默认 `1920`。

### `height_floor_rules`

这是“最低分辨率保底规则”，按顺序匹配，命中第一条就停止。

- `min_area_ratio`
  视频在页面里的面积占比阈值。
- `min_width_ratio`
  视频宽度占页面宽度的比例阈值。
- `min_height_ratio`
  视频高度占页面高度的比例阈值。
- `min_height`
  命中后，这个视频最低保到多少分辨率档位。

默认值已经调成更强调“占比越大，分辨率越高”：

- 接近全屏或占比很大：优先 `1080p`（极限压缩预设最高 `720p`）
- 摆放宽度超过页面宽度 `1/2`，或摆放高度超过页面高度 `1/2`：至少 `720p`
- 其他视频：最低 `480p`

这里判断的是视频在 PPT 页面里的摆放尺寸，也就是 shape 的宽高相对幻灯片宽高的比例，不是源视频文件自身的像素尺寸。

### `audio_rules`

音频策略按预设变化：高质量最高 `192k`，平衡最高 `128k`，极限压缩最高 `96k`。

- `min_kbps`
  最低音频码率。
- `max_kbps`
  最高音频码率。
- `rounding_step_kbps`
  音频码率按多少步长取整，默认按 `32k` 一档。
- `tiers`
  按视频页面占比给音频分层。
- `pressure_adjustments`
  当整体压缩压力很大时，音频如何继续往下收。

默认值含义：

- 大画面优先使用该预设的最高音频码率
- 中小画面按占比降到 `96k` 或 `64k`
- 目标体积压力大时，音频会按 `pressure_adjustments` 继续下调，但不会低于 `min_kbps`

### `bitrate_ladder`

这是各个分辨率档位对应的视频码率范围。当前只使用 `480p`、`720p`、`1080p` 三档。

- `min_video_kbps`
  设置目标大小时，这个分辨率档位的清晰度底线。
- `best_video_kbps`
  不设置目标大小时，这个分辨率档位的推荐码率；设置目标大小时也作为预算宽松时的上限。

默认值已经调优为：

- `1080p` 只留给占比特别大的视频
- `720p` 给大视频
- `480p` 给小视频或极限压缩里的非大画面视频

当前内置预设的视频码率表：

| 预设 | 分辨率 | 最低码率 | 推荐码率 |
| --- | ---: | ---: | ---: |
| 高保真 | 480p | 700k | 1500k |
| 高保真 | 720p | 1700k | 3800k |
| 高保真 | 1080p | 3200k | 6500k |
| 平衡 | 480p | 430k | 980k |
| 平衡 | 720p | 980k | 2150k |
| 平衡 | 1080p | 1950k | 3900k |
| 极限压缩 | 480p | 325k | 700k |
| 极限压缩 | 720p | 700k | 1500k |
| 极限压缩 | 1080p | 1400k | 2800k |

工具不会主动提高源视频分辨率、源视频码率或源音频码率；上表只是上限和目标区间。
FFmpeg 这里使用的是可变码率控制：`-b:v` 是目标平均码率，`-maxrate` 和 `-bufsize` 限制短时峰值；CPU 两遍编码通常更接近目标平均值，GPU 编码是近似控制。

目标容量以最终输出文件的真实字节数闭环，而不是只相信码率估算：超出目标最多重新
分配并编码两轮，低于目标 95% 最多回补一轮质量。任一素材未通过双尺度 SSIM 或结构
门禁时恢复原素材并停止继续降质。安全模式视频基础阈值 `0.95`、图片 `0.99`；强制版
只能由 GUI 二次确认触发，且仍执行绝对质量红线。目标模式默认 CPU 两遍，GPU 目标
模式默认关闭；Windows 会依次探测 NVENC、QSV、AMF/MF 并逐素材回退 CPU。

### 帧率规则

帧率不再按小画面强行降到 `20fps` 或 `15fps`。当前规则是：

- 高保真：保留源视频帧率。
- 平衡：只压高帧率视频，最高封到 `30fps`。
- 极限压缩：高帧率视频最高封到 `24fps`。
- 源视频低于这些上限时保持原帧率，不会升帧。

## 调参建议

- 想让大视频更清楚：
  提高 `height_floor_rules` 里大面积档位的 `min_height`，或者提高 `720/1080` 的码率上限。
- 想更激进压小视频：
  降低 `480` 的 `best_video_kbps` 或 `min_video_kbps`。
- 想保更好的音频：
  提高 `audio_rules.tiers` 里的 `target_kbps`。
- 想进一步逼近目标体积：
  把 `pressure_adjustments` 里的 `below_ratio` 调高，或者把 `reduce_by_kbps` 调大。
